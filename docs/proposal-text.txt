OVERVIEW
The idea in one page
ShopSphere  |  Marketplace + Digital Khata  |  Project Proposal
02
Small shopkeepers sell offline and keep credit records in paper registers. Buyers
want one trusted place to find products, compare prices and track orders.
ShopSphere joins both worlds: a Daraz-style multi-vendor marketplace with a
built-in Easy Khata-style digital ledger, under one account.
WHY THIS MATTERS
Sellers get shop, stock, orders and credit records in one dashboard.
Buyers get search, filters, sale prices, cart, checkout and tracking.
Admins get approvals, moderation, audit logs and reports to keep trust high.

BACKEND
Backend modules and API
ShopSphere  |  Marketplace + Digital Khata  |  Project Proposal
12
Auth
POST /auth/register, /login, /logout, /reset-password
Hashed passwords, secure sessions
Catalogue
GET /products, /products/:slug, /categories, /shops/:slug
Search, filters, pagination
Cart
GET/POST/PATCH/DELETE /cart/items
Prices read from the database
Orders
POST /orders (checkout), GET /orders, PATCH /orders/:id/cancel
Stock check inside a transaction
Seller
POST/PATCH /seller/products, /seller/orders/:id/status, /seller/shop
Only the shop owner can edit
Khata
GET/POST /khata/parties, /khata/ledger, /khata/expenses, /khata/reports
Every edit logged, balances calculated
Admin
PATCH /admin/sellers/:id/approve, /admin/listings/:id, GET /admin/audit
Admin role + audit log
Delivery
GET /delivery/shipments, PATCH /delivery/shipments/:id
Delivery role only
Rules for every endpoint: validate input, check the logged-in role and ownership, never trust totals sent by the browser.

SAFETY
Security, trust and reliability
ShopSphere  |  Marketplace + Digital Khata  |  Project Proposal
13
Server-side permissions
Roles and ownership are checked on
the server for every protected action.
Safe passwords and login
Modern password hashing, secure
sessions, safe account recovery.
No raw card data
Payments use a compliant provider;
only references are stored.
Correct prices
Totals, discounts and coupons are
calculated on the server, never trusted
from the browser.
Safe checkout
Database transactions protect stock
and order totals; no overselling.
Abuse protection
Input validation, rate limits and
protection against common web
attacks.
Privacy first
Collect only necessary data and
restrict access to sensitive records.
Audit and backups
Admin actions are logged; backups
and monitoring support recovery.
Honesty rule: a feature is described as live only after its integration is configured and tested end to end.
